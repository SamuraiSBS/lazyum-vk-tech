# P0-11.15 — Yandex Qwen: model-specific JSON Schema contract

**Проверено:** 2026-09-20 (Europe/Moscow)
**Метод:** read-only проверка официальной документации Yandex AI Studio и
текущего локального кода. Provider/API-вызовы, чтение `.env*`, генерация,
export, renderer и Docker не выполнялись.

## Вопрос и граница вывода

Проверяется именно endpoint `POST https://ai.api.cloud.yandex.net/v1/chat/completions`
и model URI `gpt://<folder>/qwen3.6-35b-a3b`: можно ли заменить текущий
`response_format: { type: "json_object" }` на OpenAI-compatible structured
output с `type: "json_schema"`, `json_schema.schema` и `strict: true`.

Официальный общий контракт endpoint это допускает. Но на дату проверки не
найден первичный источник Yandex, который одновременно и явно относит
`json_schema` + `strict: true` к **Qwen 3.6-35B-A3B**. Поэтому общий контракт
не является достаточным подтверждением model-specific контракта для внесения
diff.

## Первичные источники Yandex

1. [Create Chat Completion — API reference](https://aistudio.yandex.ru/ru/docs/ai-studio/api/Chat-Completions/createChatCompletion), проверено 2026-09-20.

   - Endpoint: `POST https://ai.api.cloud.yandex.net/v1/chat/completions`.
   - В описании `response_format`: «`json_schema` … ensures the model will
     match your supplied JSON schema»; для `{ "type": "json_object" }`
     указан older JSON mode, а `json_schema` предпочтителен «for models that
     support it».
   - API reference задаёт допустимую форму:

     ```json
     {
       "type": "json_schema",
       "json_schema": {
         "name": "example",
         "schema": {},
         "strict": false
       }
     }
     ```

   - Для `strict: true` источник говорит: модель «will always follow the
     exact schema», но также явно ограничивает режим: «Only a subset of JSON
     Schema is supported when `strict` is `true`».
   - В начале документа есть существенная оговорка: поддержка параметров
     может различаться в зависимости от модели, особенно для reasoning models.

2. [Отправить структурированный запрос — Yandex AI Studio](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/generation/completions-structured), проверено 2026-09-20.

   - Это первичный executable-пример именно для `chat/completions`: в нём
     `response_format` имеет `type: "json_schema"` и объект
     `json_schema` с `name` и `schema`.
   - Примерная модель — `gpt://<folder>/yandexgpt/rc`, **не Qwen**.
   - В опубликованном примере нет `strict: true`, поэтому он не подтверждает
     strict-режим для Qwen.

3. [Продуктовый дайджест Yandex Cloud, апрель 2026](https://yandex.cloud/ru/blog/digest-april-2026), проверено 2026-09-20.

   - Подтверждает, что «Qwen 3.6-35B-A3B уже доступна в Yandex AI Studio».
   - Для Responses API фиксирует model URI:
     `gpt://<идентификатор_каталога>/qwen3.6-35b-a3b`.
   - Также заявлены supported APIs `Responses API, Completions API` и
     включённый function calling. Эта публикация не называет
     `response_format.json_schema`, `strict` или поддерживаемые keywords JSON
     Schema для Qwen.

## Сопоставление с текущим кодом

`src/lib/yandex-ai-studio.ts:52-66` формирует запрос в существующий
OpenAI-compatible `/chat/completions` путь, передаёт model URI из config,
отключает reasoning и сегодня использует:

```ts
response_format: { type: "json_object" }
```

Комментарий к нему верно описывает текущую позицию: `json_object` шире
поддерживается данным Qwen endpoint, а полный план дополнительно проходит
локальную validation. `plannerInput()` задаёт нужное число слайдов текстовой
инструкцией и локальный контракт всё равно проверяет результат после parsing.

`src/lib/planner-provider.ts:41-74` лишь выбирает server-only Yandex adapter,
получает model URI из окружения и не задаёт response schema. Он не содержит
доказательства provider capability и не должен изменяться в этом исследовании.

Актуальный [backlog проекта](BACKLOG.md) фиксирует незавершённые пункты planner-schema и необходимость отдельной авторизации для live measurement.

## Ограничения для динамических 5–15 slides

Для schema-output требовалась бы схема с массивом `slides`, в которой
`minItems: 5` и `maxItems: 15` являются **статическими границами**, а точное
значение выбирается из request. JSON Schema сам по себе не выражает правило
`slides.length === request.slideCount`, если `request.slideCount` не встроен
в отдельную заранее сформированную схему на конкретное значение (например,
`minItems: 10` и `maxItems: 10`) либо не проверяется локально после ответа.

Следовательно, даже при будущем подтверждении strict JSON Schema нужно:

- сохранить server-side validation точного `slides.length === request.slideCount`;
- либо генерировать отдельную schema на каждый разрешённый count 5…15 с равными
  `minItems`/`maxItems`;
- не считать `minItems: 5`/`maxItems: 15` доказательством точного выбранного
  пользователем числа;
- прежде чем проектировать такой diff, подтвердить, что `minItems` и
  `maxItems` входят в model-specific strict subset Yandex Qwen.
